# CLAUDE.md

Планировщик дел. Сначала Telegram Mini App, затем веб-версия.

Суть: **план → факт → разбор отклонений → статистика**. В MVP также привычки и гибкие напоминания бота. После MVP — совместное планирование: общее свободное время с партнёрами и приватность дел.

Документы:

- `docs/requirements.md` — функциональные требования (FR-*), допущения, открытые вопросы
- `docs/architecture.md` — архитектура, модель данных, ключевые потоки, набросок API
- `docs/roadmap.md` — этапы и прогресс (отмечай выполненное)

**Не додумывай требования.** Если что-то неясно или не описано, спроси пользователя. Когда требования или решения меняются, обновляй `docs/`.

## Стек

- **Backend:** Go 1.27, `net/http` + `chi`, `pgx/v5` + `sqlc`, `goose`, `log/slog`, `oapi-codegen` (strict server), `rrule-go`, `go-telegram/bot`
- **БД:** PostgreSQL 18
- **Frontend:** React + TypeScript (strict) + Vite, TanStack Query, React Router, Zustand, Tailwind CSS, `date-fns` + `@date-fns/tz`, Recharts
- **Telegram:** Mini App (официальный `telegram-web-app.js`) и бот (long polling)
- **Инфраструктура:** `docker compose`

## Структура

```
api/openapi.yaml   контракт API — источник правды для Go и TS
backend/           Go: cmd/scheduler, internal/<фича>, migrations/, queries/
frontend/          React: src/api, src/platform, src/features/<фича>
docs/              требования, архитектура, план
```

## Команды

Все команды запускаются из корня через `make`; `/usr/local/go/bin` и `./bin` Makefile добавляет в PATH сам.

| Команда | Что делает |
|---|---|
| `make install` | `npm ci` во `frontend/` |
| `make tools` | ставит в `bin/` sqlc, oapi-codegen и golangci-lint нужных версий (`bin/` не коммитится; нужен `GOPROXY=direct`, это уже прописано) |
| `make gen` | `api/openapi.yaml` → Go (`oapi-codegen`) и TS (`openapi-typescript`); `queries/` + `migrations/` → Go (`sqlc`). Сгенерированные файлы коммитим |
| `make lint` | golangci-lint, eslint, `tsc`, проверка prettier |
| `make test` | поднимает dev-БД, затем `go test` (с `TEST_DATABASE_URL`) и Vitest |
| `make build` | бинарник `bin/scheduler` и `frontend/dist` |
| `make dev-db` | Postgres 18 на `127.0.0.1:5433` (`docker-compose.dev.yml`) |
| `make dev` / `make dev-web` | бэкенд на `127.0.0.1:8081` (с `DEV_AUTH=true`) / Vite с прокси `/api` на бэкенд |

Нюансы:

- Go-тесты с БД берут адрес из `TEST_DATABASE_URL`; без неё они пропускаются. Каждому тесту `testutil.NewDB` выдаёт отдельную схему и удаляет её по окончании.
- Новая миграция — SQL-файл `backend/migrations/NNNNN_name.sql` с секциями `-- +goose Up` / `-- +goose Down`. CLI `goose` не нужен: миграции применяются из бинарника при старте. Пока миграций нет, `sqlc generate` пропускается.
- Прокси Go (`proxy.golang.org`) на сервере отвечает 403 на часть модулей (например, `modernc.org/sqlite`). Из-за этого `go mod tidy` ругается на тесты зависимостей: запускай `go mod tidy -e`.
- TypeScript закреплён на 5.9: `openapi-typescript` пока не поддерживает 6.
- Проверка `http://127.0.0.1:8081/api/v1/healthz` — liveness и доступность БД.

Go на сервере установлен в `/usr/local/go/bin`, но в неинтерактивном shell его нет в PATH. Перед вызовом `go` выполняй `export PATH=$PATH:/usr/local/go/bin`. Системный Go — 1.23.4; модуль требует 1.27, и нужный toolchain скачивается автоматически.

## Инварианты домена

- **Время.** В БД время хранится только как `timestamptz` (UTC). Локальные даты и границы дней считаются в часовом поясе пользователя, повторы разворачиваются в часовом поясе серии.
- **Пересечения.** Дела могут пересекаться. Никаких ограничений на пересечения ни в БД, ни в API.
- **Разовые и регулярные дела.**
  - Разовое дело — строка `task_instances` без серии.
  - Регулярное — шаблон `task_series` (RRULE) плюс экземпляры, которые материализуются лениво; `UNIQUE(series_id, original_start)`.
  - Удалённый экземпляр серии — это `status = cancelled`, строка не удаляется.
- **История неизменна.** Экземпляр с фактом или со статусом, отличным от `planned`, **никогда** не меняется при правке серии.
- **Перенос.** Исходное дело получает `status = rescheduled`. Создаётся новое разовое дело с `rescheduled_from_id`. Обычная правка времени через форму переносом не считается.
- **Отклонения** («начал позже», «затянулось» и т.д.) не хранятся. Они вычисляются из плана, факта и порога пользователя.
- **Статистика** считается по факту.
  - Дело учитывается **один раз в каждой** категории из множества DISTINCT «свои категории + все их предки».
  - Общее время — объединение интервалов, без двойного учёта.
  - `rescheduled` и `cancelled` не входят в план.
- **Напоминания.** Действующие правила берутся с первого уровня, у которого есть своя строка в `reminder_settings`:
  1. `instance`;
  2. `series`;
  3. категории — у каждой свои настройки или ближайшего предка с настройками, правила всех категорий объединяются;
  4. `global`.

  `enabled = false` на уровне значит «без напоминаний». Тихие часы задаются в строке `global`.
- **Изоляция данных.** Любой запрос к данным фильтруется по `user_id` текущего пользователя. После MVP чужие данные доступны только по правилам приватности.

## Соглашения

**Общие**

- Интерфейс и документация — на русском. Код, идентификаторы, комментарии и коммиты — на английском.
- API — contract-first: сначала правим `api/openapi.yaml`, затем перегенерируем Go и TS. Сгенерированный код руками не правим.

**Backend**

- Пакеты по фичам в `backend/internal/`. Слои: handler → service → store (sqlc).
- SQL пишем только в `backend/queries/*.sql`, строки SQL в коде не склеиваем.
- Миграции — только новые файлы. Уже применённую миграцию не редактируем.
- `context.Context` — первым аргументом. Ошибки оборачиваем через `fmt.Errorf("…: %w", err)`.
- Конфигурация — только из переменных окружения.

**Frontend**

- `window.Telegram` используется только в `src/platform/telegram.ts`. Остальной код работает через интерфейс платформы — так веб-версия подключится без переписывания.
- Серверное состояние — только через TanStack Query. UI-состояние — через Zustand.
- Чистая логика — в отдельных функциях с тестами Vitest: раскладка параллельных дел, расчёт слотов, преобразование «форма повтора ↔ RRULE».
- Сетка календаря — свой компонент. Линии слотов рисуются CSS-фоном, а не отдельным DOM-элементом на каждый слот.

## Безопасность

- `initData` проверяется только на сервере: HMAC от токена бота и свежесть `auth_date`. `initDataUnsafe` для авторизации не используется.
- Секреты (токен бота, пароли БД) хранятся только в `.env`, который не коммитится. Пример — `.env.example`.
- Вход без Telegram (`DEV_AUTH`) работает только при `APP_ENV=dev`.

## Сервер

Деплоим на этот же сервер (Ubuntu, 2 CPU, 3.8 ГБ RAM). Сначала пишем весь код, деплой — последним этапом.

На сервере уже работают контейнеры чужого проекта `diary`. **Их не трогать:**

- `diary-caddy-1` (network host) — порты 80 и 443;
- `diary-db-1` — Postgres на `127.0.0.1:5432`;
- порт `127.0.0.1:8080` тоже занят.

Наши сервисы публикуем только на `127.0.0.1` и на свободных портах (dev-БД — `5433`). Как пускать внешний трафик, решаем с пользователем на этапе деплоя.
